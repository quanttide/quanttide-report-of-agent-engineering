# 量潮 AGENTS.md 报告：规矩在靠复制传播

> 生成日期：2026-10-11
> 数据来源：46 个领域仓 22811 条候选片段的全量近重复检测
> 样本口径：AGENTS.md 贡献 375 条片段，占语料 1.64%；其中 36 条卷入近重复
> 结论：**AGENTS.md 是全语料重复最密集的文件，富集 2.31 倍。原因不是疏于维护，是它天生站在那个位置。**

---

## 前言

**背景。** 我们在 46 个领域仓上跑了一遍近重复检测——把每一段话变成向量，找出讲同一件事的两处。全语料 22811 条片段，只有 946 条（4.1%）卷进近重复；其中真正需要人处理的只有 41 组。这份报告只讲其中 AGENTS.md 的那一部分。

**方法。** 本地 bge-m3 向量化（1024 维），余弦 ≥ 0.90 算近重复，把近重复连成组，再逐组读原文定类。全程离线，没花 API 钱。数字都可复算。

**立场。** 我们本来想验证一件事：AGENTS.md 是不是「没人管、各写各的」的角落。**结论是它确实是重复最密集的文件，但原因不是没人管**——把这个原因说准，比多找几个重复更有用。这份报告写给维护这些仓的人，也写给以后往仓里派智能体的人。

---

## 一、核心发现

### 发现一：AGENTS.md 是全语料重复最密集的文件

    语料里 AGENTS.md 占     375 / 22811 = 1.64%
    卷进重复的里面占         36 /  946  = 3.81%
    富集                     2.31 倍

排第二的是章程（2.3 倍），第三是 index.md（1.6 倍）。**越抽象的文件越容易重复**——AGENTS.md 是最抽象的那一类：它不说任何具体业务，只说「在这儿干活得守什么规矩」。

一句大白话：AGENTS.md 不像内容，像**贴在车间墙上的操作守则**。守则这东西，每个车间都得贴一张。

### 发现二：重复平均分成两半，两半的成因不一样

**一半是横着抄（8 组）——不同域的 AGENTS.md 抄了同一段。**

    g000  algorithm / code / connect / growth    「人机协作范式」段
    g007  credit / work                          「措辞严格使用既有术语，不用口语」
    g020  algorithm / code                        仓库自我介绍句
    g051  pay / project                           子模块提交顺序
    g053  product / strategy                      目录结构（apps / packages / examples）
    g006  code / work                             工具箱职责声明
    g032  code / think                            子模块提交顺序
    g052  pay / secret                            工具箱结构说明

**另一半是竖着抄（8 组）——同一个仓里，根目录的 AGENTS.md 与各级子目录的重抄。**

    g103  asset   根              ↔  apps/qtcloud-asset/
    g107  asset   examples/       ↔  examples/second-brain/archive/
    g062  asset   examples/       ↔  second-brain/archive/  ↔  second-brain/roadmap/    三份
    g309  pay     apps/qtcloud-pay/  ↔  apps/qtcloud-pay/src/provider/
    g308  pay     根              ↔  packages/quanttide-pay-toolkit/packages/go/
    g216  data    dart 包         ↔  flutter 包
    g065  course  data/brochure/  ↔  data/journal/  ↔  data/profile/                    三份
    g181  data

竖着抄这一半，说明一件具体的事：**子目录的 AGENTS.md 没有「只写与父目录不同之处」，而是把父目录的规矩重抄了一遍。** 这是最容易改的一类——父目录已经说过的话，子目录不必再说。

### 发现三：被复制的是纪律，不是内容

16 组里 9 组复制的是同一类东西——**干活的操作纪律**：

    最小干预 · 原子提交 · 契约优先 · fixtures 先行 · 禁止端侧发明语义
    提交推送本仓再更新主仓指针 · 子模块提交顺序

剩下的是自我介绍句、目录结构、职责声明、措辞规则、标题模板句——**全是「说明这个仓是什么、怎么在这儿干活」，没有一条是业务内容。**

### 发现四：已经抄得不一样了

复制本身不致命，**复制够多次就会分叉**。已经发生了：

`g000`「人机协作范式」段，四个仓，四种状态：

    algorithm   5 条，直角引号
    code        5 条，「提交即推送」是另一种说法：
                  「提交后默认推送到远端，除非用户明确说『只提交不推』」
                vs「修改完成后直接提交并推送，无需另行请示，除非用户明确说『只提交不推』」
    connect     6 条，多出「查询契约」和「验证优先」两条
    growth      5 条，用的是直引号 "只提交不推"——其余三份都是直角引号

`g007`「措辞严格使用既有术语」段，两份，一份短一截：

    credit  措辞严格使用既有术语，不用口语。决策思路写在开发者文档里，按「背景 / 选项 / 影响 / 建议」
            梳理清楚；不用「要你拍板」这类说法把决策推给用户。待决事项不进 `TODO.md`，TODO 只列可直接动手的事项。
    work    措辞严格使用既有术语，不用口语。决策思路写在开发者文档里，按「背景 / 选项 / 影响 / 建议」梳理清楚。

四条规矩被写成四个样子，其中三条是「同一句话的详略不同」，一条是引号风格不同。**读者（尤其是智能体）拿到哪一份就按哪一份干。**

## 二、原因推测

三条，一条比一条根本。

**第一，AGENTS.md 是规矩的载体，规矩靠复制传播。**

仓库族里没有「下发」这个机制——没有一份东西会自动出现在所有仓。想让每个仓都守住同一条纪律，只能到每个仓里写一遍。**复制是最省事、也是唯一可用的传播方式。**

**第二，复制沿着两条轴发生，而且仓内那条更隐蔽。**

横轴（域 ↔ 域）看得出来，因为跨域本来就显眼。竖轴（仓 ↔ 子目录）不容易看出来——同一个仓里的父子文件，抄一遍几乎不引人注意。数据里两条轴各占一半，说明**我们过去盯的只有横轴**。

**第三，越抽象的内容越容易被复制。**

抽象的话在哪都成立，所以在哪都得说一遍；具体的内容只说一次。这解释了富集分布：AGENTS.md 2.31 倍 > 章程 2.3 倍 > index.md 1.6 倍 > 普通正文 0.88 倍（**低于平均**）。**不是门面文件疏于维护，是它们本来就该到处出现。**

## 三、理想状况

理想状态不是「没有重复」——**规矩本来就该在每个用到它的地方出现，不然读者得跳出去看。** 理想状态是：

**同一件事只有一处算数，其余地方出现的是它的副本，而且副本是生成的，不是手抄的。**

具体到 AGENTS.md，分三层：

| 层 | 放什么 | 谁出正本 |
|:--|:--|:--|
| 族级 | 通用工作纪律（最小干预、原子提交、提交即推送……） | 一份，别处是生成副本 |
| 仓级 | 只写这个仓特有的规矩 | 各仓自己写 |
| 目录级 | 只写与父目录不同之处 | 该目录自己写，**不重抄父的** |

**一条自检判据**：AGENTS.md 里的一句话，如果能在另一个仓的 AGENTS.md 里一字不差地找到，那它就不是这个仓的规矩——它该上移。

按这个判据，现在这 16 组、36 条，一条都不该留在原地。

---

## 四、改进建议

**一、把重复的纪律收成一份正本。** 上表那 9 类（最小干预、原子提交、契约优先、fixtures 先行、禁止端侧发明语义、子模块提交顺序、工具箱职责声明、目录结构、仓库自我介绍句）各出一份，定在哪个仓由领域拍板——**我们只指出同一件事现在散在哪些仓，哪份为准是领域的事。**

**二、通用块用注入，不用手抄。** 各仓 AGENTS.md 里给通用部分留一段带标记的区间，由脚本从正本注入。改正本一处，重新注入即可。这样既保证「就地能读到」，又保证「各仓一致」——**复制可以继续，但必须是生成的。**

**三、子目录 AGENTS.md 只写差异。** 这是最容易见效的一类：8 组竖着抄，把父目录已有的话删掉就没了。

**四、先修已经分叉的四处。** `g000` 的四版（条数 5/6、引号直/直角、提交即推送两种说法）、`g007` 的两版。**这四处是唯一已经产生「两种说法」的地方，其余只是重复，没有分歧。**

**预期效果**：16 组 36 条 → 0。横轴 8 组由建议一、二消掉，竖轴 8 组由建议三消掉。

---

## 结论

**AGENTS.md 的重复不是疏于维护，是规矩只能靠复制传播——横着抄到各个域，竖着抄到各个子目录。治它的办法不是「少写几遍」，是把通用纪律收成一份正本、让副本由脚本生成、让子目录只写差异。**

顺带一句：我们本来想找「没人管的角落」，找到的却是「**管得太多、到处都管了一遍**」的地方。这两件事的解法完全相反。
